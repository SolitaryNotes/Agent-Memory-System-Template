# 机制详解

> 每条机制都按同一结构写：**它解决什么失效 → 怎么工作 → 不用会怎样**。
> 只想知道怎么用，看 `core/agent_memory/README.md`；这里回答的是**为什么**。

---

## 1. 分层链路与渐进披露

**失效**：把项目全部上下文塞进每次会话 —— 昂贵，且会稀释关键信息。

**机制**：四层，每层只包含「下一层需要时才会读取」的信息。

```
CLAUDE.md（内核）        →  BOOT.md（状态+路由）  →  current_state.md（手册+索引）  →  session_logs/（历史）
```

**判据**：一条信息该放哪层，问「每次会话都必须知道吗？」

**不用会怎样**：要么每次会话都很贵，要么 Agent 缺少必要信息而做出错误假设。

---

## 2. 内核只写协议，不写知识

**失效**：内核越写越长，最终变成一份迷你手册，每次会话都在为用不到的知识付费。

**机制**：`CLAUDE.md` 只回答「**去哪读**」，不回答「**读到了什么**」。
它包含：身份、目标、当前阶段、启动序列、快捷命令、文件放置原则、风格约定。

**不用会怎样**：内核无限膨胀。实测案例：文档写着「保持在 ~40 行」，实际长到 128 行——
因为写的时候每一条都「有用」，没人做减法。

**对策**：行数预算被 `check_conventions.py` 强制检查（默认 90 行报错 / 77 行警告）。

---

## 3. 任务 → 文件路由表 ⭐

**失效**：Agent 接到任务后找不到该改哪个文件，于是全局搜索、猜、或问你。

**机制**：`BOOT.md` 里一张两列表：**任务类型 → 需要改动的文件**。

```
| 新增实验 | experiments/run/<name>.py + configs/<name>.yaml + results/<name>/ |
| 新增图表 | experiments/plot/exploratory/{NN}-{name}.py + figures/exploratory/{NN}-{name}/ |
```

**这是全文信息密度最高的一节**，也是投入产出比最高的写作——写一次，
之后每一次新会话都受益。

**不用会怎样**：Agent 每次都要重新「发现」项目结构，这既慢又容易放错地方。

**维护**：找不到对应行时，按「同类就近」放置，**并补一行**。不补，这张表就会衰减成摆设。

---

## 4. 陈旧度信号

**失效**：Agent 读到一份状态文件，但不知道它是什么时候写的，于是把过时信息当真。

**机制**：`BOOT.md` 和 `current_state.md` 顶部强制一行
`**Updated**: YYYY-MM-DD | **Stage**: ... | **Branch**: ...`。

**不用会怎样**：文档静默腐化。Agent 无法判断「Phase 3 进行中」是今天的状态还是三个月前的。

**延伸**：`git log --oneline -15` 被刻意放在启动序列中**叙述层之前**——
先看事实，再看叙述。文档与代码冲突时，以 git 为准。

---

## 5. 产物清单

**失效**：会话结束后，Agent 找不到上次产出的文件放在哪。靠记忆检索不可靠。

**机制**：每份 session log 强制一张「产物清单」表，列出本次产生的**每一个**路径。

| 文件 | 说明 |
|---|---|
| `results/ps16/history.json` | ps=16 的训练历史 |
| `figures/exploratory/02-ps16-block-ablation/summary.pdf` | 消融对比图 |

**不用会怎样**：产物散落各处，后续会话反复问「上次那个图在哪」。

---

## 6. 索引置于手册末尾，历史目录纯追加

**失效**：如果 `session_logs/` 里放索引文件，每次新增日志都要改两个地方，
而且要读索引就得先进目录——多一跳。

**机制**：索引统一放在 `current_state.md` 的「会话日志索引」一节，
`session_logs/` 内只有日志本身，**纯追加**。

**不用会怎样**：历史目录出现自己的索引文件，与手册的索引重复且互相漂移。

**强制**：`check_conventions.py` 会检查每份日志是否登记在索引里。

---

## 7. 计划生命周期

**失效**：计划文件没有状态字段。实测案例——唯一的计划其阶段早已被实际工作取代，
却仍被两个入口文件标为「当前计划」，成为**误导性文物**。

**机制**：`plans/` 每份计划带 frontmatter：

```yaml
status: active        # active | done | superseded
superseded_by:        # 被取代时填新计划文件名
```

规则：**任何时刻 `active` 至多一份**；立新计划时把旧的标 `superseded`。

**不用会怎样**：计划目录变成堆放场，Agent 不知道该信哪份。

---

## 8. 任务简报与预写的报告格式 ⭐

**失效**：把任务派给一个新 Agent 时，它可能理解偏差、遗漏要点、或回来一堆没法用的话。

**机制**：`prompts/` 下的任务简报包含三段关键结构：

1. **启动顺序** —— 本任务该读哪几个文件（而不是让它自己猜）
2. **已知前提表** —— 包含**已被证伪**的假设，防止新 Agent 重走死路
3. **报告格式** —— 一个预写好的 markdown 骨架，把 `?` 换成实测值

第三点是关键：**规定答案的形状，而不只是问题**。它还带一个强制判据块
（✅ 完成 / ⚠️ 部分完成 / ❌ 失败）和「严禁编造数字」。

**不用会怎样**：每次派活都要重新解释格式要求，且回报质量参差。

---

## 9. `run.json` 实验溯源

**失效**：实测案例——`results/exp/` 与 `results/exp_30ep/` 的区别**只存在于文件夹名**，
结果文件里查不出 epoch 数。全仓库没有 run-id。

**机制**：每个实验结果目录写一份 `run.json`：

```json
{
  "run_id": "20260918-1430-mask-ratio-sweep",
  "started_at": "2026-09-18T14:30:00+08:00",
  "config": { "...": "本次实验解析后的完整配置快照" },
  "git_commit": "a1b2c3d",
  "seed": [0, 1, 2],
  "duration_sec": 5400,
  "note": "为什么跑这一轮"
}
```

Schema 见 `modules/research/run.schema.json`。

**不用会怎样**：无法回答「这个数字是哪次跑出来的、当时的配置是什么」——
而这正是**复现**和**写论文**时最常要回答的问题。

**注意**：这是本系统唯一强制的 schema。实验结果表本身的列名**不做统一**，
理由见 `design.md` 第四节。

---

## 10. 单一事实源与生成

**失效**：`CLAUDE.md` 与 `AGENTS.md` 手工双写。实测案例——两份文件在
「当前阶段」「最近会话」「快速开始命令」三处互相矛盾。

**机制**：`CLAUDE.md` 是唯一源；`AGENTS.md` 由 `tools/sync_agents_md.py` 生成。
平台专属内容用成对标记包裹，不会进入 `AGENTS.md`：

```markdown
<!-- @agents:skip -->
## Claude Code 专属
...
<!-- @agents:endskip -->
```

**不用会怎样**：两份文件持续漂移，且没有机制会发现。

---

## 11. 可执行校验

**失效**：所有约定都靠人记。实测案例——镜像规则写进了每个脚本的 docstring，
仍然出现了重复编号和孤儿目录。

**机制**：`tools/check_conventions.py` 校验 10 项：**模板路径残留**、**路径引用死链**、
行数预算、AGENTS 同步、陈旧度、日志命名与索引、计划生命周期、镜像规则、编号唯一性、
`run.json` 存在性。

死链检查的覆盖范围（**有意收窄，别想当然**）：项目根的 `CLAUDE.md`/`AGENTS.md`/`README.md`、
`agent_memory/` 下的常驻文档（不含日志/计划/简报）、任意深度的 `README.md`、以及全部 `.py`。
**不覆盖** `docs/`、`cloud/package/`、`meetings/` 的模板与历史文件——那里的路径多为举例。
`.py` 能被覆盖是因为一个便利性质：**反引号在 Python 里不是合法语法**，
所以被反引号包起来的路径 token 一定出现在 docstring 或注释里，是散文引用而非代码。

其中最后两项（**残留在前两条**）是冷启动验收逼出来的，都属于同一类：「文档里的路径不可信」：

- **模板路径残留**：模板仓库里写作 `modules/cloud/docs/x.md`，落地后应是 `cloud/docs/x.md`。
  漏改一处，读者就走进一个项目里根本不存在的路径。这条检查**零假阳性**——
  已落地的项目结构里没有 `modules/` 这一层，任何出现都是残留。
- **死链**：文档引用了不存在的文件或目录（实测抓到：路由表引用的 `configs/` 目录根本没建）。

这类问题人眼极难发现——**作者知道自己的意思，读者却会走进死胡同**，所以必须机器查。

**不用会怎样**：约定随时间衰减，且衰减是不可见的——直到某天自动化工具因为编号冲突而失效。

**定位**：它不是 lint 工具，是**防衰减机制**。建议挂到提交前或每天跑一次。

---

## 12. 冷启动验收 ⭐

**失效**：你写了一套自认为清晰的启动文档，但**你永远不会知道它在别人眼里是什么样**——
因为你知道背景。这是「作者盲区」，靠自省无法消除。

**机制**：每次显著改动记忆系统后，**开一个全新的子 Agent**，给它零上下文，
只丢一句「读 `CLAUDE.md`，按它的 Boot Sequence 走」，然后要求它回报三件事：

1. 这个项目是什么、现在什么状态
2. 启动序列在哪里**断了**或**需要猜**
3. 有没有哪个文件"看起来像真实产物但其实是模板"

**必须要求它给出批评性意见**，并写明「说『一切正常』只有在属实时才有用」——
否则子 Agent 会倾向于报喜，测试就白做了。

> **本节是验收轮次的唯一台账。** 其它文档提到"做了多少轮"时应指向这里，
> 不要各写各的——本模板自己就犯过这个错（汇总行写 13、正文记到 14）。

**它真的有效。** 本模板前后做了 **14 轮**验收，每轮都抓出真问题，且**每轮的发现类型都不同**：

| 轮次 | 抓到的代表性问题 | 提炼出的**类别** |
|---|---|---|
| 1 | `plans/_TEMPLATE.md` 的 frontmatter 写着 `status: active`——"读那份 active 计划"会读到**冒充真实计划的空模板**；`git log` 那步在未 `git init` 的项目里直接失败且无 fallback；`CLAUDE.md` 引用的 `tools/` **根本没被复制进项目** | 模板冒充真实产物 / 断链 |
| 2 | 路由表引用的 `configs/` 目录不存在；`modules/research/run.schema.json` 这条**只存在于模板仓库的路径泄漏进了项目**；`RESULTS_SO_FAR.md` 声称"已确认、可直接依赖"却全是空的 | 断链 / 自我拔高 |
| 3 | 停止规则只覆盖"全 TODO"和"全真实"两种情形，**混合情形无法归类**；`hooks/README.md` 的示例注入内容带着**另一个项目的真实阶段名**；"直接把 TODO 改写成真实内容"在空项目上**等于授权编造项目身份** | 逻辑漏洞 / 跨项目串味 / **授权编造** |
| 4 | 模板仓库路径残留在 `meetings/_TEMPLATE-*.md`；仪表盘模板把**源项目的产物名**（`q2b_fullfactorial_matrix.csv`）硬编码成默认值；`run.schema.json` 强制要求 `git_commit`，而项目未 `git init` —— **逼 Agent 编造一个 hash** | 跨项目串味 / **授权编造** |
| 5 | 一份文档指向了不存在的 playbook 路径；多处"**实测**…差 0.0034"丢失了出处，被读成本项目自己的数据；`BOOT.md` 的改写指引**没有重复内核里的空脚手架例外**，单读它会诱导填假内容 | 断链 / 假数据归属 / 规则不一致 |
| 6 | `meetings/` 模板指向一个**永远不会落地**的 `README.md`；「改写 TODO」的祈使句排在免责例外**之前**，读者可能先动手再读到例外；`BOOT.md` 断言 `Branch: main` 而项目根本不是 git 仓库 | 断链 / **指令顺序** / 断言与事实不符 |
| 7 | 文档里写的 `verify_integrity.py` 命令行**与该脚本的实际参数不符**，照抄直接报错；`core:` 这个前缀从未定义过；`.gitignore` 注释里残留 `modules/cloud`；示例数据（`84 runs`、`mse 0.3853`、格子代号）**单独看无害，凑在一起就成了可引用的假事实**；空内容判据的排除清单没覆盖 `tools/` 之外的脚手架代码 | 断链 / 跨项目串味（组合效应）/ 判据不严密 |
| 8 | `docs/` 里一堆指向不存在章节的引用；子 Agent 自造的 `E_G_xxx` 标记**从没定义过**，读者只能当成真实内容；未经标记的「4 卡 A100 代替 8 卡 V100」被读成本项目的硬件方案；判据的排除清单漏了 `docs/` 下的空白模板（它**长得最像内容**） | 断链 / 未定义标记 / 示例未标记 / 判据覆盖不全 |
| 9 | `current_state.md` 预置了一条 `- [x] [TODO: 已完成的事项]`——**一个"已完成但不知完成了什么"的勾选项**，唯一能让它自洽的办法就是编造功绩；同时 `hooks/session_start.py` 把它数成真实待办；我第七轮的修复把 `Stage` 正则撑到了行尾，hook 输出变成「验证 \| **Branch**: main…」 | **结构性诱导编造** / 修复引入新缺陷 |

五条最值得记住的教训（**这一段原本写"三条"、下面却列了四条**——声明与内容对不上，正是本节要治的病）：

1. **善意指令在极端情况下会变成编造许可。** 第 3 轮的"直接把 TODO 改写成真实内容"、
   第 4 轮的"每个 run.json 必须填 `git_commit`"，本意都是"让 Agent 别卡住"，
   但都隐含了"无中生有"的许可。**凡是要求填写某字段的规则，都要显式写出该字段无值可取时怎么办。**
2. **跨项目串味比断链更隐蔽，且有组合效应。** 断链会让 Agent 撞墙（它至少知道自己不知道）；
   而一个带着别的项目阶段名的示例、一句没有出处的"实测数字"，
   会让 Agent **自信地相信一件假事**。更麻烦的是：**单个例子看起来只是"示例"，
   几个凑在一起就构成了一套自洽的假事实**——第 7 轮的 `84 runs` + `mse 0.3853` +
   格子代号，就是被这样读成本项目数据的。
3. **最危险的不是"没写"，而是"写了但内容是空的"。** 第 9 轮抓到的那条
   `- [x] [TODO: 已完成的事项]` 是全文最恶劣的一处：它**声明了一件已经发生的事，
   却不说是哪件事**。面对它，Agent 只有两条路——留着一个自相矛盾的状态，或者编一件事。
   同样性质的还有"必须填 `git_commit` 但项目没有 git"。
   **凡是要求"填一个值"的模板槽位，都要显式写明「无值可取时怎么办」。**
4. **修复本身会引入新缺陷。** 第 6 轮我修掉一处断链时写错了章节号，第 7 轮抓了出来；
   第 7 轮我修 hook 的正则时把捕获组撑到了行尾，第 9 轮又抓了出来。
   所以**每轮修复之后必须再跑一轮验收**——收敛是靠"再验一次"保证的，不是靠"这次改对了"。
5. **验收报告必须逐条复核，不能整段照收。** 零上下文能消掉**作者盲区**，
   但消不掉"**从正确观察推出错误解释**"这个失效模式。实测第 13 轮：两个 Agent 独立地、
   言之凿凿地报出同一条发现（"脚手架把 `tools/__pycache__/*.pyc` 发给了项目"），
   而它是错的——那个 .pyc 是**运行校验器的副作用**，init.py 一直在专门滤掉编译产物。
   **两个独立 Agent 得出同一结论，只说明它们走了同一条推理路径，不说明它是对的。**
   照收未复核的验收结论，等于把作者盲区换成了审计者盲区。

**第 10–12 轮：循环为什么不收敛。** 做到第 9 轮时，每轮仍能找出 6–10 处。
这不是"快干净了"，而是方法本身有问题——**冷启动是抽样，不是普查**。
于是改成三个审计 Agent 分片覆盖全部文件、按缺陷类别逐一过。审计又暴露出两类此前从未被任何一轮发现的缺陷：

- **工具在错误语境下运行。** 我给落地项目写的检查（模板路径残留、死链），
  在模板仓库里跑必然是一片假警报——因为模板仓库的文档**就是**按落地后的结构写的。
  十二轮冷启动都没发现，因为审计的是内容，没人审计**工具本身适用的语境**。
- **跨片缝隙。** 分片审计让每片内部自洽，但片与片之间的不一致（hook 认得了脚手架态、
  校验器却还把它报成"更新于 0 天前"）没人负责。**分片能并行，缝合必须有人做。**

这类问题自省发现不了：作者知道自己的意思，也知道哪些数字来自别的项目。
**只有让一个真的什么都不懂的 Agent 去执行，才会暴露。**

**第 13 轮：改去审计工具自己。** 前 12 轮审计的都是**内容**与**工具适用的语境**，
没人审计过**检查器自己的判据在哪里失效**。这轮换了做法：先把模板按默认模块落地成一个真项目，
再放**两个**零上下文 Agent 进去——一个按本节给足前提，一个**只给原始那一句话**做对照
（后者才能验出"文档自身够不够"，而不是"前提提醒在兜底"）。抓到两类新缺陷：

- **检查器自身的盲区。** `--only <已知但不适用的检查名>` 会打印「共 0 项检查 / 0 条结果」
  并**以退出码 0 通过**——源码注释把这种情况称为"比检查失败危险得多"，却只拦了未知名字。
  另外 `PATH_TOKEN_RE` 要求结尾 `/` 之后至少还有一个字符，于是 `` `meetings/` `` 这类
  **裸目录引用**整条匹配不上，造成**报警倒挂**：被散文明确豁免的 `cloud/README.md` 照报，
  真正悬空、且没有任何豁免的 `meetings/` 谁都看不见。
- **假警报的训练效应。** 默认只装 research 的项目一落地必然报 7 条指向 cloud/hooks 的"断链"，
  而文档明写着"未安装的模块路径不存在是正常的"。警告多了，真正的那条会被一起划过去。

**同一个缺陷，两条修法，只有一条对。** 上面那条"裸目录引用看不见"，第一反应是**放宽正则**
（把结尾的 `+` 改成 `*`）。改完落地一测：默认配置**立刻多出 3 条误报**——`common.py` 里
"（如 `models/`、`data/`）"的举例、以及相对 `experiments/` 讲的 `plot/`；装全模块时多 7 条——
`cloud/archive/README.md` 里的目录树、相对 `cloud/` 讲的 `package/`、以及**只存在于 zip 内部**、
在项目里本就不该存在的 `cloud_package/` 与 `cloud_scripts/`。也就是说：**这个生态里的裸目录 token
绝大多数出现在举例与相对叙述里**，按字面校验它们，噪音远大于收益。老老实实数一遍误报数，
就会在改之前就知道这一点。**放宽的代价是 10 条误报，而它想治的那一条，用语义判据
（`uninstalled_module_prefixes`：这个路径属于一个**没装**的模块）一行就解决了。**
正则已改回原样，并在注释里写清了这次测量——免得下一个人重做一遍这个实验。

**这一轮还留下一条方法论教训：冷启动的结论本身也要复核。** 两个 Agent 独立地、言之凿凿地
报告了同一条发现——"脚手架把编译产物 `tools/__pycache__/*.pyc` 发给了项目"。实测是**错的**：
那个 .pyc 是**运行校验器的副作用**（`check_agents_sync` 里 `from sync_agents_md import ...`），
init.py 有 `_is_build_artifact` 专门滤它。两个 Agent 都从"这个文件不该在这儿"这个**正确观察**
出发，推出了一个**错误的原因**——而它们的一致反而让它显得可信。
**零上下文能消掉作者盲区，但消不掉"从正确观察推出错误解释"这个失效模式**，
所以验收报告必须逐条复核，不能整段照收。

**第 14 轮：修完再验，抓到的比第 13 轮更狠。** 按"每轮修复之后必须再跑一轮验收"的规矩，
把上面那批修复落地后又放了一次（这次还特意让一个 Agent 去读**装了全部模块**的落地实例——
上一轮两个 Agent 都只看默认落地，`cloud/`、`meetings/`、`hooks/` 的内容从没被冷读者读过）。
抓到的问题里，最值得记的是这一条：

> **`BOOT.md` 顶部那行「首次会话后请改为真实更新日期并删掉本段斜体」，是一张写在文档里的
> 假绿灯授权书。** 照它字面办事——哪怕这个会话什么都没产出——删掉标注后，`staleness`
> 唯一的脚手架判据（字面量「脚手架初始化」）就消失了，一份 **100% 是 `[TODO]` 的状态文件
> 会被校验器盖章为「✅ 更新于 0 天前」**。已实测复现。

它暴露的是一个普遍形状：**工具层的守卫，不能只依赖文档层的自愿标记。** 标注是"文档说它自己
还没填"，挡不住一个照着文档办事的 Agent 把它删掉；而 `[TODO]` 是"内容确实还没填"，
**改不掉**（除非真去填）。所以 `staleness` 现在还会数 `[TODO]` 的处数，把
「更新于 0 天前」变成「更新于 0 天前（但仍有 13 处 `[TODO]` 未填——这份状态还不能当作已维护过）」。
顺带修掉一个自己挖的坑：判据原本对**整个文件**做子串匹配，解释这条规则的段落里一提及那几个字，
文件就永远退不出脚手架态——现在锚定在**陈旧度信号所在的那一行**。

同一轮还抓到两条"改了 A 面、B 面还开着"的老毛病（正是上面第 4 条教训的翻版）：
「首次会话后」这个措辞在 `README.md` 修了、在 `BOOT.md` / `current_state.md` 的模板里没修；
`BOOT.md` 路由表写 `results/<name>/run.json`（扁平），而协议与 schema 都写深两层。
**修一处口径不一致时，要 grep 出这条口径的每一个落点**，别只修你最先看到的那个。

**成本**：一次子 Agent 调用、几十秒。相对于它发现的问题，可以忽略。

**副产品**：验收逼出了 `check_conventions.py` 的两条检查——**模板路径残留**与**死链**，
把"文档里的路径不可信"这一类问题从"靠人眼"变成"机器查"。

> 这条机制值得固化成习惯：**只要动了记忆系统，就跑一次冷启动验收。**
