# hooks/ — 可选的会话自启动（**默认关闭**）

> 本目录默认**不生效**。它只是把「启动序列」从一条**文字约定**变成**机制**的现成零件。
> 启用前请先读完下面的开销说明再决定。

---

## 为什么默认关闭

记忆系统的启动序列（`CLAUDE.md` → `BOOT.md` → …）原本靠 Agent 读到指令后自觉执行。
把 Agent 的自律换成 hook 的强制，好处是**不会再漏**，代价是**每次会话都付固定上下文成本**。

按本仓库的实现，注入内容约 **4–6 行 / ~60–100 token**：

```
[记忆] BOOT.md 更新于 <日期>，已 N 天未更新 ⚠️
[记忆] 当前阶段：<从 BOOT.md 的 Stage 字段读取>
[记忆] 待办树中有 N 项未完成 → current_state.md §7
[记忆] 活跃计划：plans/<文件名>
[记忆] 最近会话：session_logs/<文件名>
[记忆] 完整启动序列见 CLAUDE.md 的 Boot Sequence 一节
```

> 上面的示例刻意用占位符而不是真实内容——**真实示例会被误读成本项目的状态**，
> 尤其在冷启动场景下。这不是假想问题：本模板的一次冷启动验收里，
> 示例中的阶段名差点被当成被测项目的当前阶段。

**项目还没跑过任何一次会话时**（`BOOT.md` 仍是初始化脚本写的脚手架态），第一行会换成明确的
「尚未开始」信号，而**不报天数**——脚手架日期是初始化脚本盖的章，报成「更新于 0 天前」
会把一份从未维护过的状态文件伪装成新鲜的状态：

```
[记忆] BOOT.md 仍是脚手架状态（尚无真实会话），日期 <日期> 不代表项目进度
```

判断依据是 `BOOT.md` 里有没有「脚手架初始化」这句标注；首个真实会话把它改掉之后，
才会回到上面那种「更新于 N 天前」的报法。

对短会话，这份成本占比不低；对长会话可以忽略。**判断标准：如果你经常开短会话问一句话，就别开。**

---

## 启用方法

把下面这段合并进项目的 `.claude/settings.json`（**合并**，不要整体覆盖已有内容）：

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|clear",
        "hooks": [
          {
            "type": "command",
            "command": "python \"$CLAUDE_PROJECT_DIR/hooks/session_start.py\""
          }
        ]
      }
    ]
  }
}
```

> Windows 上如果 `python` 不在 PATH，把 `python` 换成 `py` 或解释器绝对路径。

也可以用 `/update-config` 技能来描述你的需求，让它替你改配置——比手改更稳。

## 验证

新开一个会话，看是否出现 `[记忆] ...` 开头的若干行。没出现的话：

```bash
CLAUDE_PROJECT_DIR=. python hooks/session_start.py   # 直接跑，看输出
```

脚本本身**不会抛错**：任何文件缺失都静默跳过，异常也被吞掉。hook 报错阻塞用户会话，
比它不工作要糟得多——这是刻意的设计取舍。

## 关掉

从 `settings.json` 里删掉 `hooks.SessionStart` 那一段即可，脚本文件留着不影响。
