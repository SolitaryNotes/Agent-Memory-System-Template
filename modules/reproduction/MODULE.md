# modules/reproduction — 复现他人已发表工作（paper replication）

> 本模块是 `core/agent_memory/` 的**场景增量**，不替换核心。
> 核心回答「记忆放哪、什么时候更新」；本模块回答「**复现别人论文时，还需要额外记什么**」。

---

## 一、什么时候该挂载本模块

只要任务满足**任意一条**，就该启用：

- 目标是**让别人论文里的数字在自己的环境里再次出现**（严格复现 / 近似复现 / 只复现某几张表）。
- 需要把**自己的结果与论文报告值并列比较**，并解释 gap。
- 需要**在别人的方法上做改动**（改掩码策略、换 backbone、加模块），而此时「哪些是原论文的、哪些是我改的」必须可追溯。

反之，纯自研、无对照论文的项目不需要本模块——核心记忆系统够用。

---

## 二、本模块防御的三种失败模式

复现类工作的坑不在「跑不起来」，而在「**跑起来了但你不知道跑的是什么**」。

### 失败模式 (a)：静默复现了一个**不是论文**的配置

论文写「learning rate 1e-3」，但表注里写「with layer-wise lr decay 0.75」；论文正文说 masking ratio 90%，但附录表里那行数字是 95% 跑的。

**危险在于它不报错。** 代码能跑、loss 能降、指标能出——你只是复现了另一个方法。等到与论文对不上时，你已经浪费了几天算力，而且**无法判断**是自己实现错了还是配置取错了。

→ 对策：`docs/reproduction_protocol.md.tmpl` 的**逐条参数对照表**，强制把每个关键参数的「论文值 + 出处（第几节 / 哪张表）」写下来。凡是没填出处的参数，都还没确认过。

### 失败模式 (b)：拿自己的数跟论文的数比，但**不知道 gap 是真差异还是方差**

论文报 87.4%、你跑出来 86.1%（**数字为示例**）。这是：
- 实现有 bug？→ 需要查
- 硬件/精度差异（fp32 vs amp）？→ 可能可接受
- 只是 seed 方差？→ 什么都不用做

**这三种情况需要完全不同的行动，但它们的表象是一样的。** 没有方差估计，就无法区分；没有 baseline 对齐记录，就无法排除第二种。

→ 对策：本模块反复强调 **seeds and repeats**（见第四节），以及 `docs/baseline_alignment.md.tmpl` 的对齐清单。

### 失败模式 (c)：**丢失了偏离清单**——不知道自己在哪一步离开了原论文

复现过程中必然有妥协：某依赖版本装不上、某数据集子集拿不到、某 augmentation 库行为不一致。这些改动当时都「显然无害」，一周后全部忘记。

后果：**当结果对不上时，你无法定位是哪个偏离造成的**；当结果**对上了**时，你无法声明「这是在偏离 X/Y/Z 的条件下复现的」，结论强度被高估。

→ 对策：`docs/reproduction_protocol.md.tmpl` 的**允许的偏离清单**——每条偏离必须显式登记并附理由，且**在跑之前**登记，不是跑完之后补。

## 三、三个文件怎么配合

```
docs/reproduction_protocol.md   每篇论文一份：目标 / 参数对照 / 偏离清单 / 判据 / 降级方案
        ↓ 引用
docs/baseline_alignment.md      对齐核查：数据 / 预处理 / 指标实现 / seed / 精度 + baseline 差异表
        ↓ 结果写入
agent_memory/session_logs/      逐次会话的原始数值（mean±std, n）
```

| 文件 | 粒度 | 何时写 |
|---|---|---|
| `docs/reproduction_protocol.md` | 一篇论文一份 | 动手**之前**立项时 |
| `docs/baseline_alignment.md` | 一篇论文一份（或一个 baseline 一份） | 第一次跑通 baseline 时 + 每次改环境后复核 |
| `session_logs/` | 每次会话 | 会话结束（核心约定） |

> **反模式**：把参数对照表写进 session log。session log 是**时间线**，参数对照表是**状态**。状态会变，时间线不会；把状态塞进时间线，改一次就得翻十个文件。

## 四、本模块最强调的一点：seeds and repeats

**这是从真实项目里换来的教训，不是通用建议。**

### 真实教训

某项目做随机掩码（random masking）实验。初始想法是「用固定 seed 保证可复现」。**这个做法是错的**——原因：

- 随机掩码的**实验变量本身就是随机性**（这次掩的是哪些 patch 会影响结果）。固定 seed 等于把「随机性」这个变量钉死成一个特定取值，**测的是「这个 seed 下好不好」，不是「这个策略好不好」**。
- 用 seed 固定后，A 组与 B 组的差异里混入了「A 恰好抽到好掩码」的可能，且**无法估计**这个可能有多大。

**实际采用的做法**：
- 每个条件跑 **N = 3 次重复**（repeat），每次用不同的随机性（不同 seed / 不同 mask 采样）。
- 记录**每次重复的原始值**（per-rep raw values），再报 **mean ± std**。
- **只有**「随机对照组的 seed」是显式 pin 死的——因为对照组的作用是提供一个**固定参照**，它必须每次都一样。

### seed vs repeat 的判断规则

| 场景 | 做法 | 理由 |
|---|---|---|
| 随机性**是**实验变量（随机掩码、随机初始化、随机采样策略） | **repeat N≥3**，报 per-rep + mean±std，**不** pin seed | 要把「随机性带来的波动」本身估计出来 |
| 随机性**是**噪声，不是变量（数据划分、dataloader shuffle） | **pin seed**，固定住 | 消除无关变异，让条件之间可比 |
| **对照组 / baseline** | **pin seed**，全组共用同一 seed | 提供固定参照；对照组动了就没法比 |
| **要跟论文数字比** | 先 **repeat N≥3** 得到自己的均值与方差，再比 | 没有方差就无法判断 gap 是否显著（失败模式 b） |
| 算力极紧，只能跑一次 | 跑一次 + **显式记录**「n=1，无方差估计」 | 诚实标注不确定性，别假装它是稳定值 |

**一句话**：**seed 用来消除无关变异，repeat 用来度量有关变异。** 分不清某个随机性属于哪一类时，选 repeat——它的信息量严格更大。

### 记录格式（写进 session log 与结果表）

```
# 以下数值全是示例（虚构占位），务必替换成自己的实测值
condition: {{CONDITION}}
n = 3
reps = [0.3853, 0.3912, 0.3807]      # 原始值，保留，不要只留均值
mean ± std = 0.3857 ± 0.0053
seed_policy: 每 rep 不同随机种子 (reps use seeds [1,2,3])
notes: 对照组 seed 固定为 0
```

> **只保留 mean±std 而不保留 per-rep 原始值是常见错误。** 后期要换统计检验、要剔除异常 rep、要算中位数时，原始值没了就只能重跑。

## 五、模板占位符约定

- `{{PLACEHOLDER}}`：需要填写的内容（如 `{{PAPER_TITLE}}`）。
- `[TODO: ...]`：需要**调研后才能确定**的内容（如 `[TODO: 确认论文用的是 ImageNet-1k 还是 21k 预训练]`）。
- 表格中留空的单元格表示「尚未确认」，**不是「不适用」**——不适用请显式写 `N/A`。

## 六、挂载检查表

复现项目启动时逐项过：

- [ ] 建立 `docs/reproduction_protocol.md`，参数对照表的「论文值」列已填且**每行都有出处**
- [ ] 明确复现目标等级（严格 / 近似 / 只复现某表）
- [ ] 建立 `docs/baseline_alignment.md`，指标实现一节已核对
- [ ] 决定每个实验变量的 seed 策略（pin 还是 repeat），写进 protocol
- [ ] 允许的偏离清单已登记（**在开跑前**）
- [ ] 成功判据已写成**数值**（不是「差不多就行」）
- [ ] 失败降级方案已写
